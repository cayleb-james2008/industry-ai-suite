# BacktestGuard

Quant researchers detect leakage, overfitting, or unsupported conclusions before sharing an experiment. This limited real-data chronology slice checks an observation-year split and routes the findings to a quant research reviewer; it does not evaluate a supplied experiment record.

The normal command `python3 -m apps.backtestguard` reads 15 actual World Bank U.S. GDP observations and keeps the existing default split: training 2011–2020, holdout 2021–2025. To choose another split, pass `--cutoff-year YEAR` (for example, `python3 -m apps.backtestguard --cutoff-year 2018`). The selected year must be present in the live observations and leave both partitions non-empty; an invalid cutoff is reported as `DATA_UNAVAILABLE`, with no default, fixture, cache, or substitute split. Output includes the chosen cutoff, both year lists, source identifiers/hash/terms/as-of values, and a future-year leakage warning. It remains explicitly `LIMITED` and not a completed backtest: the external experiment, target/return definition, and source release timing are `UNVERIFIED`, so the full research-integrity job remains `UNVERIFIED`. There is no broker, order, strategy execution, promotion, or publication adapter. Synthetic tenant CSVs remain only for labelled `run_demo()` adversarial regression tests and are not used by the normal command.

When the suite runner is explicitly invoked with `--ai-configured`, a task-limited model may provide one evidence-cited explanation for the human reviewer; it cannot establish experiment validity or change the `UNVERIFIED` job verdict. Its result is `AI CANDIDATE (unwitnessed)` until the independent witness is verified. Without that optional route the workflow remains deterministic. Run `python3 -m apps.backtestguard --help` for command options and `python3 -m unittest discover -s apps/backtestguard -p 'test_*.py' -v` for the app checks.
